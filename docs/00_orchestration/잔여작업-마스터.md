## 5-A. ⛔ 잔여 목록에 올리는 기준 — 「누가 손해를 보는가」

> 2026-08-08 주인님 지적으로 신설. **이 관문을 통과하지 못한 항목은 잔여작업이 아니다.**

항목을 올리기 전에 **한 줄로** 답한다. 답이 안 나오면 올리지 않는다.

```
누가(고객 / 주인님 / 아무도) · 언제(지금 / 조건부 / 발생 불가) · 무엇을 잃는가
```

**금지** — 아래는 그 자체로 잔여작업이 아니다. 게이트 경고 수치 · 린트 경고 · "조문에 있는데 코드에 없음" ·
"이론상 가능한 경쟁 상태" · "더 나은 구조". **누가 손해 보는지 못 적으면 목록에 못 올린다.**

**분류 3단**

| 등급 | 정의 | 처리 |
|---|---|---|
| **A. 고객이 지금 겪는다** | 방문·접수·마이페이지에서 실제로 보이거나 막힌다 | 잔여작업 — 즉시 착수 대상 |
| **B. 주인님만 겪는다** | 관리자 화면 한정 | 목록 하단. **주인님이 불편하다고 하실 때만** 착수 |
| **C. 아무도 안 겪는다** | 발생 조건이 성립하지 않는다(예: D3는 관리자 2명 필요, 실제 1명) | **목록에서 내린다.** 조건이 생기면 그때 올린다 |

**현재 분류(2026-08-08 15:37 기준)**
- **A(고객이 지금 겪음)** = ~~옅은 글씨 10곳~~ **✅ 해소** → 남은 A는 **애니메이션 3곳**(`MyRequestsView`×2 · `AppShell:780`, 10분)뿐이다.
- **B(주인님만 겪음)** = C4 포커스 10곳 · N2 alert 1곳 · C6 관리자 92곳 · C5 관리자 4곳. **요청하실 때만.**
- **C(발생 불가)** = D3 동시편집(관리자 1명). 목록에서 내림 — 관리자가 2명이 되면 그때 A/B로 올린다.

## 5. 이 문서를 낡지 않게 하는 규칙

2026-08-07 문서가 하루 만에 낡은 원인은 **처리 기록이 worklog에만 남고 잔여 목록에 역반영되지 않은 것**이다.

1. **잔여 항목을 처리하면 그 턴에 이 문서의 해당 행을 §2로 옮긴다.** worklog 기록만으로 끝내지 않는다.
2. **잔여 목록은 이 문서에만 둔다.** 다른 문서에 같은 목록을 복제하지 않는다(제10조).
3. **판정 근거는 항상 실측**(file:line·grep 건수·테스트·게이트 수치). "~일 것이다"는 쓰지 않는다.
4. **착수 전 이 문서의 실측을 다시 돌린다.** 문서를 믿고 착수하지 않는다 — 오늘 22건이 그렇게 발견됐다.
