## 2. 실행 순서 — 이 순서를 바꾸면 헛일을 한다

```
① 삭제  →  ② 중복 제거  →  ③ 분해
```

**분해를 먼저 하면 지울 코드까지 옮기게 됩니다.** 삭제가 끝나야 남은 것의 진짜 크기가 보이고, 중복이 정리돼야 쪼갤 경계가 선명해집니다.

### ⚠ A1은 "완전히 죽은 코드"가 아닙니다 — 검증관이 제 전제를 뒤집었습니다

제가 계속 "`mock-data.ts` 1,393줄은 한 번도 실행되지 않는다"고 말씀드렸는데, **틀렸습니다.**

`.env.example`이 `NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co`를 싣고 있고 파일 2행이 "이 파일을 `.env.local`로 복사하여 사용하십시오"라고 지시합니다. 그대로 복사한 개발 환경에서는 `isPlaceholder = true`가 되어 **Mock이 실제로 돕니다.**

프로덕션(실 키)에서는 확실히 안 돕니다. 그래서 **삭제는 가능하지만, "오프라인 개발 모드를 버린다"는 결정이 선행**되어야 하고 `.env.example`·`README`(37·96·104행)를 함께 고쳐야 합니다. 그 결정 없이 지우면 개발 환경이 깨집니다.

## 8. 착수 전 주인님 결정 1건

**오프라인 개발 모드(Supabase 키 없이 로컬 실행)를 버릴 것인가.**

- **버린다** → A1 실행. 1,514줄 삭감. `.env.example`·`README` 동기 필요.

이 답이 없으면 ①단계에서 가장 큰 항목이 착수되지 않습니다.
