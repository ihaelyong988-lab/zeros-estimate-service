## 0. 왜 매주 새 오류가 나오는가 — 근본 원인과 대책

### 원인 (실측)

| 항목 | 현재 상태 |
|---|---|
| 테스트 파일 | **0건** |
| 테스트 러너 | **없음** |
| CI(푸시 시 자동 검사) | **없음** (`.github` 디렉터리 자체가 없음) |
| `npm run test` | **스크립트 없음** |

15,000줄 프로덕션 앱이 고객 개인정보와 돈을 다루는데 **자동 검출 장치가 0**이다.
그래서 결함을 찾는 유일한 수단이 "사람 또는 AI가 손으로 전수 조사"이고, 조사할 때마다 새로 나온다.
이건 작업자의 문제가 아니라 **구조의 문제**다. 조사를 반복하는 한 이 사이클은 끝나지 않는다.

### 대책 — 조사를 그만두고 그물을 깐다

핵심 관찰: **돈 버그 7건이 전부 순수 함수 3개 파일에 있다.**
`lib/calculations.ts`(124줄) · `lib/quote/quoteDraft.ts`(140줄) · `lib/quote/quoteXlsx.ts`(153줄)
→ UI·브라우저·DB가 필요 없어 테스트가 싸고 빠르다. **테스트 18개면 7건 전부 커버되고 같은 유형 재발이 0이 된다.**

| 단계 | 조치 | 효과 |
|---|---|---|
| 1단계 (이번) | vitest 도입 + 돈 로직 테스트 18개 + CI | 돈 버그 재발 0, 푸시 시 자동 검사 |
| 2단계 (다음) | 테스트 보호 범위를 유틸·API 계약으로 확대 | 조사 범위가 "이번 주 변경분 UI"로 축소 |
| 상시 | 새 결함 발견 시 **반드시 실패 테스트로 먼저 고정** 후 수정 | 같은 결함 구조적 재발 불가 |

**목표 상태**: 주간 작업이 "전수 조사 → 발견 → 수정"에서 **"기능 추가 → 테스트 통과 확인"** 으로 바뀐다.

## 1. ⛔ 착수 전 확정 필요 — 주인님 결정 4건

적대 검증 결과 **FAIL**. 아래 4건은 "순서로 피할 수 있는 충돌"이 아니라 **같은 코드에 대한 두 개의 정답**이라 병합이 불가능하다. 결정 없이 착수하면 나중에 들어간 쪽이 앞엣것을 지운다.

### 결정 ①. 미수금(`outstandingAmount`)의 정의

현재 코드는 계약금 전액을 미수금으로 잡는데, 판정 기준이 **출장견적비(수만~수십만원) 결제 여부**다.
→ 3억 수주 + 출장비 30만원 미결제 = 미수금 3억. 반대로 30만원만 받으면 계약금을 한 푼도 못 받아도 미수금 0원.

| 안 | 정의 | 결과 |
|---|---|---|
| **A** (권고) | 서비스 수수료 기준 = Payment 행(청구−수납) | 미수금이 억 단위 → 수십만원대로 급감. **정상이지만 기존 숫자와 크게 달라짐** |
| B | 계약금 수납 필드를 신설해 별도 관리 | 정확하지만 입력 항목이 늘고 운영 부담 증가 |

> ZEROS는 시공사가 아니라 견적 서비스이므로 A가 도메인에 맞다고 판단하나, **대시보드 숫자가 급변하므로 주인님 확인이 필요하다.**

### 결정 ②. 견적 초안 배분의 반올림 잔차

기준액 4,000만 → 라인아이템 합계가 **40,150,000**(+15만). 공수 반올림 때문이다.

| 안 | 처리 | 결과 |
|---|---|---|
| **A** (권고) | 마지막 항목에서 잔차를 정산해 합계를 기준액과 정확히 일치 | 합계 = 4,000만 정확. 테스트가 단순해짐 |
| B | 현행 유지(잔차 허용, ±0.5% 내) | 코드 변경 최소. 테스트 기대값이 복잡해짐 |

### 결정 ③. 사업소개 CTA 문구

`app/page.tsx:439`의 **"무료 견적 검토 신청"** 을 실제 과금 정책에 맞게 고칠지 여부.
문제: 이 문구는 `AGENTS.md §10`(140행)에 **문자열째 확정된 조문**이다. 바꾸려면 조문 개정이 선행돼야 한다.
현재 사업소개 본문은 같은 구간을 "소정 수수료"로 설명하고 있어 **CTA와 본문이 서로 모순**이다.

| 안 | 조치 |
|---|---|
| **A** (권고) | 조문 개정 + CTA를 정책에 맞게 수정 (구 값은 `agents-archive.md`에 1행 기록) |
| B | CTA 유지, 본문 설명을 CTA에 맞춤 |
| C | 이번엔 보류 |

### 결정 ④. 고객 등급 백필

`customer_grade_manual` 분리 시, 기존 '중요고객'·'보류고객' 행을 1회 복사하지 않으면 **배포 즉시 관리자 화면의 등급·필터가 바뀐다.**
→ 백필 SQL을 실행할지, 운영자가 재지정할지 결정 필요.
