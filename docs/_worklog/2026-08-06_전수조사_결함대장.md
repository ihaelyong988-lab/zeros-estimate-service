**근거**: 라우트 전체가 `body.password` → `safeEqual(password, ADMIN_PASSWORD)` → 401 뿐이다. import 목록에 `crypto`·`NextRequest`·`createAdminSession` 세 개뿐이고 `lib/otp/rateLimit.ts`(이미 저장소에 존재, OTP 라우트 2곳이 사용 중)는 쓰이지 않는다. 실패 카운터·지연·잠금·IP 버킷 어느 것도 없고, 루트에 `middleware.ts` 도 없어(파일 미존재 확인) 상위 계층 방어도 없다. 반면 훨씬 파급이 작은 `/api/otp/verify:25` 는 `rateLimit('verify:phone:'+phone, 5, 10*60*1000)` 로 막혀 있다 — 정작 가장 강한 권한만 무방비다.

**재현/시나리오**: 잔여작업대로 Vercel에 `ZEROS_ADMIN_PASSWORD` 를 등록한 직후, 공격자가 `curl -X POST https://zerospipe.co.kr/api/admin/login -H 'Content-Type: application/json' -d '{"password":"zeros1234!"}'` 를 스크립트로 반복한다. 서버는 매번 401만 돌려줄 뿐 차단하지 않으므로 초당 수십~수백 회 대입이 가능하고, 사람이 고른 비밀번호(구 기본값 `zeros1234!` 포함)는 사전 대입 수 분~수 시간 내 적중한다. 적중 즉시 응답으로 `adminToken` 을 받고, 그 토큰으로 `POST /api/data {op:'list',table:'zeros_customers'}` 를 호출해 전 고객 이름·휴대폰·이메일·현장주소·견적금액을 통째로 내려받는다. 이어 `/api/files/sign` 에 같은 토큰을 실으면 버킷의 모든 도면·사진·견적서 서명 URL이 발급되고, `op:'upsert'`·`op:'deleteEstimate'` 로 이력 위변조·영구 삭제까지 가능하다.

**영향**: 고객 — 이름·휴대폰·주소·도면 등 개인정보와 영업정보 전량 유출(개인정보보호법 신고 대상). 주인님 — 견적·결제·방문 이력 위변조 및 영구 삭제로 30년 실적 데이터 손실. 운영자 — 침해 사실을 알 수단조차 없다(로그인 실패 로그·알림 미구현).

**처방**: `app/api/admin/login/route.ts` 의 POST 진입부에 기존 `lib/otp/rateLimit.ts` 의 `rateLimit`/`clientIp` 를 적용한다 — 예: `rateLimit('adminlogin:ip:'+clientIp(req), 5, 15*60*1000)` 초과 시 429 + `Retry-After`. 인메모리는 인스턴스별 베스트에포트이므로(§13 H-5와 같은 한계) 추가로 (a) 실패 응답 전 고정 지연 1초를 넣어 대입 단가를 올리고, (b) `safeEqual` 의 단일 sha256 비교를 scrypt 검증으로 바꿔 회당 비용을 올린다. 완전 방어는 공유 저장소(Redis) 카운터 — §13이 OTP에 대해 이미 적어둔 후속과제를 관리자 로그인에도 같이 적용한다.

#### D25. 관리자 토큰에 비밀번호의 무염 SHA-256 프리픽스가 들어 있어 토큰 1회 유출으로 비밀번호가 오프라인 크래킹된다

| | |
|---|---|
| 위치 | `lib/otp/token.ts:112` |
| 분류 · 난이도 | 보안 · S |
| 조사 축 | 서버·보안·데이터 계층 |
| 검증 | 미검증 — 착수 전 재확인 필요 |
| 조문 접점 | 없음. |

**근거**: `function adminPasswordTag(): string { const pw = process.env.ZEROS_ADMIN_PASSWORD || ''; if (!pw) return ''; return crypto.createHash('sha256').update(pw).digest('base64url').slice(0, 16); }` — 서버 SECRET 이 섞이지 않은 **순수 sha256(비밀번호)** 의 앞 16자다. 이 값을 `createAdminSession()`(:120)이 `sign({ t:'adm', k: adminPasswordTag(), exp })` 로 페이로드에 넣고, `sign`(:27-30)은 페이로드를 base64url 로만 인코딩하므로 누구나 디코딩해 읽는다. 이 토큰은 `lib/files/secureFile.ts:14` 에서 localStorage `zeros_admin_token` 에 저장되고 `lib/supabase/client.ts:778·798` 에 의해 **모든 /api/data 요청 본문에 실려 나간다.**

**재현/시나리오**: 관리자 PC의 브라우저 확장·공용 단말·백업된 localStorage·개발자도구 화면 공유 등으로 `zeros_admin_token` 문자열 하나가 노출된다. 공격자가 `atob(token.split('.')[0])` 로 `{"t":"adm","k":"Xk3f...","exp":...}` 를 읽고 사전+규칙으로 `sha256(후보).base64url.slice(0,16)` 를 GPU에서 초당 수십억 회 대조한다. 무염 단일 sha256이라 KDF 지연이 없어 사람이 고른 비밀번호는 수 분 내 복원된다. 토큰 자체는 8시간이면 만료되지만(:108) 복원된 **비밀번호는 만료되지 않으므로** 공격자는 이후 언제든 `/api/admin/login` 으로 새 토큰을 정상 발급받는다.

**영향**: 주인님 — 8시간짜리 사고로 끝났어야 할 토큰 유출이 영구 계정 탈취로 확대된다. 비밀번호를 다른 서비스와 공유하고 있다면 그쪽까지 번진다. 고객 — 결과적으로 전 PII·전 파일 유출(1번 항목과 동일 피해).

**처방**: `lib/otp/token.ts` 의 `adminPasswordTag()` 를 `crypto.createHash('sha256')` 대신 이미 있는 `hmac()`(:23, 서버 전용 SECRET 사용)으로 바꾼다 — `return hmac('adminpw:' + pw).slice(0, 16);`. 서버 SECRET 없이는 후보 대조 자체가 불가능해져 오프라인 크래킹이 원천 차단되고, '비밀번호 변경 시 기존 토큰 일괄 폐기'라는 설계 의도(:105-107 주석)는 그대로 유지된다. 배포 시 기존 관리자 토큰이 무효화되어 재로그인만 필요하다.

**근거**: catch 블록이 `{ error: e instanceof Error ? e.message : '데이터 처리 중 오류가 발생했습니다.' }` 로 응답한다. `loadRows`(:88)가 `throw new Error(error.message)` 로 Supabase/PostgREST 원문을 그대로 올리므로 이 값은 DB 오류 문구다. 같은 파일 209행 `return Response.json({ error: error.message }, { status: 500 })`·356행도 동일하고, `app/api/files/sign/route.ts:101` 은 `파일 링크 생성에 실패했습니다: ${error?.message}` 로 Storage 오류를 노출한다. 503 메시지들(`app/api/data/route.ts:114`, `app/api/files/sign/route.ts:72`, `app/api/admin/login/route.ts:28`)은 미설정 환경변수 이름(`SUPABASE_SERVICE_ROLE_KEY`·`ZEROS_ADMIN_PASSWORD`)까지 그대로 알려준다.

- **결정 ①** 공개 실적 지표 정책 — 사업소개 `246건`(상수) vs 실적 탭 `101건`(DB, 99건이 테스트 시드). 미결
- **결정 ②** 모바일 홈 `#041B33` 조문 이행 — 미결
- C2(모바일 홈 리컬러) · C4(`focus:outline-none`) · C5(`motion-reduce`) · C6(본문 대비, 3개 파일만 처리됨) ·
  C7(종료 팝업 '닫기' 무반응) · C8(좌측 공종 선택 URL 미반영) · C9(플레이스홀더) · C10(헤더 터치 타깃 3건) ·
  D1(게이트 룰 4종 + `--all` 스윕) · D2(`mock-data` 동적 import) · D3(단건 쓰기) · D6(죽은 3초 인터벌) · D7(Storage 익명 업로드 제한) ·
  B4(검토 비율 100% 초과 가능 — **B1 적용으로 `work_type` 값이 8종 밖으로 나갈 수 있게 되어 발생 조건이 실제로 열렸다**) ·
  B5(CTA 명칭 5종 혼재) · B8(AI 품목표 편집 소실) · B9(이메일 형식·방문일 범위·새 등록 초기화·시간대 임시저장) · B11 — 처리됨(C1과 함께 삭제)
