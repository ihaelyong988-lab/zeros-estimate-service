## 3. 기수가 잡아낸 계획 오류 2건

계획서가 틀렸고 기수가 코드를 직접 읽어 바로잡았다. 지시대로 했으면 회귀였다.

1. **"3초 인터벌은 죽은 코드"는 틀렸다.** `app/page.tsx:280-285`의 인터벌이 갱신하는 `activeTradeIdx`는 데스크톱 견적검토 히어로(`renderReviewDesktop`)가 **살아서 소비**한다. 죽은 것은 셸 컨텍스트 브리지뿐이었다. 지웠으면 데스크톱 공종 순환이 멈춘다.
2. **C5 범위가 12지점이 아니라 19지점**이었다. 탐색 정규식이 `animate-*` 유틸리티만 보고 `<style dangerouslySetInnerHTML>` 주입 CSS와 인라인 `style={{animation}}`을 놓쳤다. → D1 게이트 룰에 그 스캔을 넣어 같은 누락을 구조적으로 막았다.

## 3-A. 적대 검증(3기)이 배포 전 잡은 것 — FAIL 2건 봉합

### FAIL ① D7 — `allowed_mime_types` 는 방어가 0이고 정상 첨부만 막는다

검증관이 반증에 성공했다. 세 가지가 동시에 참이었다.

1. **방어값 0** — MIME 은 `lib/supabase/storage.ts:61`이 `file.type || 'application/octet-stream'`으로 **클라이언트가 신고**하는 값이고, dwg·hwp 때문에 목록에 `application/octet-stream`을 넣어야 한다. 그 순간 무엇이든 통과한다.
2. **정상 업로드만 막는다** — AutoCAD·한컴이 설치된 Windows(= 이 서비스의 주 고객 환경)는 레지스트리에서 `application/x-dwg`·`drawing/dwg`·`application/haansofthwpx` 등 목록에 **없는** 값을 보낸다. 거부되면 `RequestWizard`가 `err.message`를 그대로 띄워 중장년 고객이 Supabase 영문 원문을 본다.
3. **주장한 위협을 막지 못한다** — 개당 50MB 상한은 객체 수·총량·요청 빈도를 제한하지 않는다. `50MB × N회`는 그대로 가능하다.

→ **봉합**: `allowed_mime_types` 절 삭제, `file_size_limit`만 유지. MIME 커버리지 테스트 2건을 제거하고 **"설정하지 않는다"를 테스트로 고정**했다. 형식 검증은 확장자 기준 `validateFileFormat`이 담당한다는 사실과 근거를 SQL 주석에 남겼다.

### FAIL ② N6 — 삭제 op만 만들고 호출부가 0건이었다

`deletePayment`가 `/api/data` op와 `ZerosService` 메서드로는 신설됐으나 **이를 호출하는 관리자 UI가 저장소 전체에 0건**이었다. 결함대장 N6의 실제 결함(오입력 청구 행을 지울 경로가 없다)은 운영자 관점에서 그대로 남고, **호출자 없는 관리자 엔드포인트만 공격 표면에 추가**된 상태였다.

→ **봉합**: `EstimateDetailModal` 기청구 행에 삭제 버튼 + 되돌릴 수 없음을 알리는 확인 단계. 견적의 결제 상태·미수금은 남은 행 집합에서 파생되므로 행만 지우면 지표가 따라온다.

### PASS 판정 (반증 시도 후 통과)

`N6` 권한 3계층·파생 미저장(§14-4 기계 고정) · `D2` 동적 import(판정 순서·초기화 순서·동시성 안전) · `§13` 불변식(익명 견적 분기 순서·PII 제거·브라우저 직접 접근 금지) · `B8` 초안 저장이 총액이 아닌 **공급가액**만 저장 · `B9-a` 이메일 정규식이 실주소 배터리에서 오탐 0.

1. **하단 탭 활성 라벨 대비 3.23:1** — 오렌지 `#E0701A` on 화이트, 12px라 4.5:1 미달. **비랜딩 4개 탭은 원래부터 3.23:1**이었고 C2로 랜딩만 5.12 → 3.23으로 떨어졌다. 활성 오렌지는 앱 전역 내비 어포던스라 임의 변경 금지. 처방 후보: 활성색을 `text-steel`(8.6:1)로 내리거나, 오렌지 유지 + 활성 표시를 상단 인디케이터 바로 이동.
