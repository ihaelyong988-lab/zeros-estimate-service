## 2. 위중 결함 3건 조치 (서브에이전트 3기 병렬, 파일 배타 소유)

### ① 인증번호 화면 노출 차단 (P0 보안)
SMS 키 미설정 상태(현 프로덕션)에서 서버가 인증번호를 응답에 실어 보내고 화면에 표시하던 문제. 타인 휴대폰 번호만 알면 무인증 로그인 → 그 사람의 견적 전문·현장주소·도면·견적서 열람이 가능했다.

- `app/api/otp/send/route.ts` — 응답의 `devCode` 필드 제거(`testMode`는 유지). 인증번호는 서버 로그로만.
- `components/forms/PhoneVerifyGate.tsx` · `components/forms/CustomerLoginModal.tsx` · `components/MyRequestsView.tsx` — `testCode` state·setter·표시 블록(이모지 "⚙️ 테스트 모드" 포함) 삭제. 삭제 자리에 단정형 안내 한 문장.
- **부작용(의도됨)**: SMS 키 등록 전까지 마이페이지 로그인은 인증번호를 받을 수 없다. 접수 위저드는 `/api/otp/status`로 게이트를 건너뛰므로 영향 없다. 지금은 아무나 타인 계정에 들어갈 수 있는 상태이므로 막는 것이 맞다.
- `verify` 라우트의 인증 강제(fail-closed)는 **넣지 않았다** — 키 미등록 상태에서 강제하면 접수까지 중단된다.
- 검증: `devCode`·`testCode` grep 0건.

### ② 익명 API 영업정보 유출 차단 (P0 보안)
`stripEstimate`가 PII 9종만 지우는 차단목록 방식이라, 인증 없는 요청에 견적 품목 단가(`line_items`)·견적금액·확정 계약금액·실주사유·담당자 등이 그대로 반환됐다.

- `app/api/data/route.ts` — **허용목록(`PublicEstimate`)으로 전환.** 공개 실적 화면 실사용 필드만 반환: `id`·`created_at`·`work_type`·`site_type`·`estimate_category`·`status`·`estimate_sent_at`.
- 실사용처(`components/PerformanceInsights.tsx`·`lib/calculations.ts`)를 직접 대조해 `estimate_sent_at`(평균 소요일 산출)을 포함시켰다.
- 차단목록은 `Estimate`에 필드가 추가될 때마다 조용히 누출되므로 구조적으로 폐기. 고객 세션·관리자 경로는 불변.

### ③ 방문 이력이 수주 실적을 삭감하던 버그 (P0 데이터 무결성)
`createSiteVisit`/`updateSiteVisit`이 견적의 현재 상태와 무관하게 `현장방문 예정/완료`로 덮어써, `updateEstimate` → `syncCustomerOnStatusChange`가 수주 취소로 판정해 고객의 `total_won −1`·`total_revenue −계약액`을 실제 DB에 기록했다. '취소' 방문도 '예정'으로 매핑됐다.

- `lib/supabase/client.ts` — `VISIT_SYNCABLE_STATUSES` 화이트리스트(`EstimateStatus` 타입 기반) 신설 + `syncEstimateStatusForVisit()`로 동기화 로직 분리.
  - 방문 이후 단계(견적서 송부완료·수주성공·수주실패 등)는 **상태 보존**
  - `visit_status === '취소'`면 상태 미변경
  - 이미 같은 상태면 저장·알림 생략(멱등)
  - 방문 레코드 저장 자체는 그대로 작동
- `syncCustomerOnStatusChange` 본체는 미변경(호출 조건만 차단).
