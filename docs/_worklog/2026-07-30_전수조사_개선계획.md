## 7. 중단 규칙 (자동 실행 중 판단 기준)

1. **W0 빌드 실패** → Next 업그레이드만 롤백, Wave 1 계속. install 자체 실패 시 `git checkout -- package.json package-lock.json && npm ci`.
2. **Wave 종료마다 임시 커밋을 남긴다**(`git commit -m "wip(waveN): ..."`). 커밋이 없으면 병렬 3기가 같은 워킹트리에 쓴 변경에서 특정 Wave분만 되돌리는 것이 **물리적으로 불가능**하다. 이 임시 커밋들은 W4-C에서 squash한다.
3. **어느 Wave든 `npm run build` 실패** → 직전 Wave 커밋으로 되돌리고(`git reset --hard <직전 wip>`) 원인 기록 후 다음 Wave 진행. 실패를 안고 최종 커밋하지 않는다.
4. **확정 조문과 충돌하는 개선안** → 실행하지 말고 **보고만**(§8 판정 보류 목록).
5. `master` 직접 커밋 금지 — Wave 0 착수 전 `fix/audit-2026-07-30` 브랜치를 만들고 그 위에서만 작업한다.
6. **프로덕션 배포는 자동 실행 범위 밖이다.** master 머지·푸시는 GitHub 연동 호스팅의 즉시 배포를 트리거하는데, ①OTP fail-closed가 SMS 키 미등록 상태로 나가면 고객 로그인·접수가 전면 중단되고 ②이번 변경 폭이 넓어 무인 배포 위험이 크다. **브랜치 푸시까지만 자동, 배포는 주인님 승인 후.**

## 8. 판정 보류 — 실행하지 말고 보고할 것

- **★ 조문 모순: "본문 ≥16px"(§10) vs "홈 1366×768 한 화면 수납"(O-37).** 홈 히어로 본문 4개소(`page.tsx:1952`·`1984`·`1993`·`2002`·`2051`)는 11.5~14.5px로 §10 위반이지만, 16px로 올리면 카드당 +90~100px가 발생해 O-37 세로 예산을 초과한다(루트 `overflow-hidden`이라 스크롤이 아니라 **클리핑**된다). O-37이 "3문장 고정"이라 텍스트 축약 흡수도 막혀 있다. **어느 방향으로 가도 조문 위반이므로 주인님 결정 전까지 손대지 않는다.** 선택지: ⓐ O-37 예산을 늘려 카드 높이 상향 ⓑ 3문장을 2문장으로 완화 ⓒ 홈 히어로를 §10 본문 규칙의 예외로 명문화.
- **반응형 조건 렌더 전환**(`isMobileLayout`으로 모바일/데스크톱 트리 분기): 성능 이득은 크지만, O-38이 확정한 `sm:`/`md:` 분기 값 검증 기준 자체를 무효화할 수 있다. 별도 판단 필요.
