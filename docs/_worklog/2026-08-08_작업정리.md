## 2. 기수가 스스로 멈춘 것 — 지시보다 코드를 믿었다

**A7(`Estimate.payment_status`·`payment_required` 삭제)을 계획서가 "확실"로 분류했는데 담당 기수가 거부했습니다.**

읽는 곳이 0인 것은 맞았으나, **타입 계약이 자기 소유 밖 3파일에 걸려 있었습니다** — `lib/payments/status.ts:10`(§14-2 보호 모듈의 타입 파생) · `RequestWizard.tsx:585`(살아 있는 쓰기) · `test/fixtures.ts:34-35`. 지웠으면 세 파일에서 tsc가 깨졌습니다.

**A10도 절반만 했습니다.** 저장 카운터의 *가산 경로*는 지웠지만 `types/estimate.ts`의 필드 3종은 남겼습니다. `CustomerList.tsx`가 8지점에서 직접 읽는데, 그 값이 저장값이 아니라 **읽기 시점에 파생값이 실려 오는 전달 통로**였기 때문입니다.

계획서를 그대로 실행했으면 둘 다 사고였습니다. "계획서를 믿지 말고 네가 직접 grep 하라"는 지시가 값을 했습니다.

## 3. 적대 검증이 잡은 것 — FAIL 1 + 잔재 2

### FAIL — `tsconfig.json` `resolveJsonModule` 삭제가 성립하지 않는다

담당 기수는 `npx tsc --noEmit` 0에러로 안전을 주장했으나, **강제 주체가 tsc가 아니라 `next build`** 였습니다. Next.js 16이 이 옵션을 mandatory로 취급해 빌드마다 되돌려 넣으면서 `tsconfig.json` 전체를 재직렬화합니다.

→ 순효과: **축소 0 + 빌드마다 추적 파일이 더러워지는 새 부작용.** 복구했고, 사유를 주석으로 박았습니다. 빌드 후 `git diff`로 재작성 흔적 0을 확인했습니다.

### 잔재 2건 (봉합 완료)

- `test/api/dataRoute.test.ts:72` — 삭제된 `hasServiceKey` export를 `vi.mock`이 계속 반환
- `EstimateDetailModal.tsx:1260` — 화면에 **"로컬 Mock DB에 반영됩니다"** 문구가 남아 있었다. Mock을 지운 지금은 명백한 거짓이고, 사실 삭제 이전에도 이미 거짓이었다(§9)
