## 5. 접수목록 페이지네이션

검색·필터·정렬은 이미 있었고 **페이지네이션만 없었다**. 25건 기본 + "N건 중 a–b" + 이전/다음 + 페이지 크기(25/50/100). 검색·필터·정렬이 바뀌면 1페이지로 되돌린다.

**측정**: 접수 246건 기준 렌더 행 **246 → 25** (−89.8%).

## 6. 데이터 캐시

관리자 탭 한 번 전환에 최대 6회 풀스캔이 일어나던 것을 in-flight 병합 + 30초 TTL 캐시 + 쓰기 직후 무효화로 줄였다.

**이 작업의 핵심 안전 조건은 캐시가 권한 경계를 넘지 않는 것이다.** 같은 테이블이라도 관리자·고객·익명에게 서버 응답이 다르다(§13). 캐시 키에 관리자 토큰만 넣으면 스테일 토큰이 남은 브라우저에서 다른 고객 행이 샌다.

담당 기수가 **신원 구성요소를 전부 키에 넣고**(`admin:<token>|customer:<phone>:<session>`) 그 이유를 주석으로 남겼다. 읽고-고쳐-쓰기 경로는 캐시를 우회해 lost update도 막았다.

## 9. 남은 것 (다음 차수)

- **`mock-data` 정적 import** — `lib/supabase/client.ts:4`가 `./mock-data`(55KB/1,406줄)를 정적 import 한다. `isSupabaseEnabled`가 항상 true라 `MockZerosService`는 실행되지 않는데도 고객 첫 로드 번들에 실린다. 동적 import로 돌리면 추가 절감이 가능하다.
- **첫 진입 시 `zeros_estimates` 요청 2건 동시 발생** — in-flight 병합이 이 조합을 잡지 못한다. 중복 출처 확인 필요.
- **스플래시 카피 중복** — `AppShell` 스플래시와 `app/page.tsx` 히어로에 같은 문장이 두 곳에 있다. 한쪽만 고치면 SSR 본문과 실제 화면이 어긋난다. 상수로 뽑는 것이 근본 처방.
- **사업소개 탭 데스크톱 1366×768에서 51px 세로 오버플로** — CTA 하단은 750.88로 조문(≤768)을 통과하며 넘치는 51px은 CTA 아래 후행 여백이다. 이번 변경이 만든 것이 아니다.
- **관리자 화면 육안 확인** — `ZEROS_ADMIN_PASSWORD` 미등록으로 로그인이 503이라 지연 로드된 관리자 화면의 실제 렌더를 브라우저로 확인하지 못했다. 키 등록 후 대시보드·칸반·상세 모달 1회 확인을 권한다.
- **Vercel 이미지 최적화 사용량**이 새로 발생한다(`minimumCacheTTL` 1년으로 재최적화 빈도는 최소화).
